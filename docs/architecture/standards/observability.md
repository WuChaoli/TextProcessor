# 可观测性标准

## 信号模型

TextProcessor 使用日志、指标和链路追踪三个互补信号。业务任务状态以 PostgreSQL 为权威来源；观测系统不得承担状态转换、幂等或审计事实存储。

## 统一关联字段

| 字段 | 用途 | 约束 |
| --- | --- | --- |
| `service` | 区分 API、worker 和能力服务 | 使用稳定低基数名称 |
| `environment` | 区分部署环境 | 不包含主机或凭据 |
| `request_id` | 关联一次入口请求 | 可进入日志和 trace，不作为指标标签 |
| `task_id` | 关联后台任务生命周期 | 可进入日志和 trace，不作为指标标签 |
| `caller_id` | 调用方隔离与诊断 | 日志中使用安全标识，不记录认证材料 |
| `trace_id` / `span_id` | 跨服务关联 | 遵循 OpenTelemetry 上下文 |
| `error_code` | 聚合稳定业务错误 | 不使用异常正文作为标签 |

## 结构化日志

- 使用 structlog 输出机器可解析事件，每条日志包含时间、级别、服务、环境和事件名。
- API 入口、任务入队、状态转换、worker 开始/结束、重试、外部调用、发布和恢复使用稳定事件名。
- 默认禁止记录原始文本、文档正文、凭据、Authorization/Cookie、完整 URI 查询参数、内部堆栈和宿主机绝对路径。
- 预期业务错误记录稳定 error code 和安全摘要；内部异常只在受控日志中保留经过脱敏的信息。
- Loki 负责收集和查询日志。保留期、访问控制和租户隔离由部署配置定义。

## 指标

- FastAPI 使用 Prometheus 兼容指标，至少覆盖请求数、错误数和延迟。
- Celery 与能力服务覆盖任务状态、队列等待、处理耗时、重试、超时、外部依赖和资源饱和度。
- 标签必须是有界集合，例如 route template、method、status class、task type 和 stable error code。
- 禁止把 `request_id`、`task_id`、caller、文件名、URI、异常正文或用户输入放进标签。
- 指标端点必须受网络边界或认证保护，不对任意公网暴露。

## 链路追踪

- OpenTelemetry context 从 API 传播到 Celery 消息和内部 HTTP 调用；消费者创建独立 span 并保留因果关系。
- span 属性只记录协议、稳定操作名、状态、耗时和经过批准的低风险元数据。
- Celery 消息仍只携带任务协议所需字段；trace context 使用标准消息头传播，不把完整任务参数复制到消息或 span。
- exporter 不可用不得阻塞业务主路径；丢弃、缓冲和降级行为需要可观测。

## 展示与告警

Grafana 统一展示 Prometheus 指标、Loki 日志和所选 trace 后端。仪表盘至少覆盖 API 健康、任务积压、失败/重试、处理延迟、外部依赖和资源使用。告警必须绑定可行动的症状和 runbook，避免仅因单次异常触发噪声。

## 性能诊断

- memray 用于受控环境的内存分配、泄漏和峰值分析，产物按敏感诊断数据管理。
- py-spy 用于低侵入 CPU 采样和火焰图，不作为持续 profiling agent。
- 在生产附加 profiler 前必须确认权限、性能影响、采集范围、保存位置和清理方式。
- 诊断结果记录提交、运行环境、负载、采样时长和工具版本，避免把一次采样当作长期性能结论。

## 验收

可观测性能力只有在真实服务产生信号、采集链路可查询、敏感字段检查通过且故障降级经过验证后才算完成。仅添加依赖、配置示例或仪表盘 JSON 应报告为部分完成。

## 当前迁移边界

本标准描述目标状态。仓库当前未提供足够证据证明 structlog、Prometheus、OpenTelemetry、Loki、Grafana、memray 或 py-spy 已完整接入；实施前相关能力均不得报告为通过。
