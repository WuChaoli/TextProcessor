# 本地路径访问能力策略设计

## 1. 背景与问题

当前结构化提取、Markdown 清洗、全局去重和文本分类分别通过输入或输出根目录配置限制调用方提供的本地路径。API 接收请求时校验路径是否位于白名单根目录，worker 在读取输入或发布结果时再次执行类似检查。

这种机制要求部署方提前枚举业务目录。137 服务器上的调用方将输出目标指定为 `/data/shineData/hub/txt/*.md` 时，即使目录存在且服务账号具备访问权限，只要该目录未被运行中的 `EXTRACTION_OUTPUT_ROOTS` 覆盖，API 就返回 `OUTPUT_PATH_NOT_ALLOWED`。把白名单扩大为 `/` 也不能完整解决问题：API 与 worker 使用不同配置，且 worker 的 `/` 输出根会包含内部 staging，从而触发 staging 与输出根重叠校验。

本次变更取消调用方本地业务路径的根目录白名单，改为统一的访问能力检查。服务是否能够读写某个本地路径，以实际运行账号的文件系统权限和操作结果为准。

## 2. 目标

- 结构化提取、Markdown 清洗、全局去重和文本分类使用一致的本地路径访问语义；
- 调用方提供的本地输入可以位于任意目录，只要是可访问的现存普通文件；
- 调用方提供的本地输出可以位于任意目录，只要父目录存在且可写；
- API 在提交阶段快速预检，worker 在实际读取或发布前重新验证；
- 移除本地业务路径对 `*_INPUT_ROOTS`、`*_OUTPUT_ROOTS` 的依赖，不保留白名单开关或双模式；
- 保持内部 staging、远程输入策略、输出冲突、原子发布和错误脱敏等边界；
- 在 137 的真实 systemd 运行账号下验证可访问和不可访问路径行为。

## 3. 非目标

- 不放开 HTTP host/CIDR、S3 bucket、协议、凭据、大小或超时限制；
- 不允许调用方指定、替换或扩大内部 staging 目录；
- 不自动创建调用方指定的输出父目录；
- 不改变目标文件默认不覆盖的语义；
- 不提升 API 或 worker 的 Linux 权限，不使用 root 权限绕过文件系统访问控制；
- 不改变处理器选择、文本处理算法、任务状态机或 API 的异步任务模式；
- 不把本地路径访问能力扩展为长期文档资产管理或任意远程资源访问能力。

## 4. 选定方案

新增共享的 `LocalPathAccessPolicy`，作为所有能力访问调用方本地业务路径的唯一策略。各业务模块保留格式、大小和协议等领域校验，但不再自行维护根目录归属判断。

策略分为输入和输出两类操作：

- 输入检查接收调用方路径，验证其为绝对路径、存在且为普通文件，并确认服务进程能够实际打开读取；
- 输出检查接收调用方目标文件路径，验证其为绝对路径，父路径已存在且为目录，并确认服务进程具备发布文件所需的写入能力；
- 路径是否允许不再由配置 roots 决定，最终以 API 或 worker 运行账号的权限和实际文件操作结果为权威；
- 输出目标已经存在时仍按现有幂等与冲突规则处理，不通过访问策略覆盖。

共享策略只处理调用方业务路径。内部 staging 继续由各 worker 的服务端配置控制，不能通过请求参数改变，也不复用“任意可访问路径”的语义。

## 5. 本地输入语义

本地输入依次满足以下条件：

1. 请求值是当前操作系统语义下的绝对路径；
2. 路径能够正常解析；
3. 目标在检查时存在且是普通文件；
4. API 预检能够以只读方式打开文件；
5. worker 消费任务时重新以只读方式打开文件，并以实际打开结果为准；
6. 文件大小、后缀、内容类型和各能力已有格式规则继续生效。

不再判断解析后的路径是否属于任何输入根目录。符号链接按照操作系统实际解析结果访问，不再具有“逃离白名单”的概念；目标不存在、形成循环、解析失败或运行账号不能读取时均按输入访问失败处理。目录、设备、socket、FIFO 等非普通文件不能作为输入。

API 的成功预检不构成 worker 后续成功读取的保证。文件可能在入队后被删除、替换或修改权限，因此 worker 必须重新检查并安全失败，不能因为 API 曾经通过而跳过实际打开。

## 6. 本地输出语义

本地输出依次满足以下条件：

1. `targetPath` 是当前操作系统语义下的绝对文件路径；
2. 目标父目录能够正常解析、已经存在且是目录；
3. API 在不创建业务产物的前提下完成快速可写性预检；
4. worker 发布前重新确认父目录状态，并通过真实的安全发布操作验证写权限；
5. 目标文件不存在，或者符合本任务已有的幂等恢复条件；
6. 发布仍采用临时结果校验后原子落盘的现有模型，不暴露半成品。

服务不为调用方创建缺失的父目录。单独依赖 `os.access` 不能证明后续写入一定成功，尤其在权限变化、ACL、挂载状态或并发修改场景中；因此预检只用于尽早返回错误，worker 的实际创建、链接、重命名或打开结果才是最终依据。

取消输出 roots 不取消目标冲突、文件级原子发布和恢复校验。调用方指定已存在的普通目标文件时，除现有幂等恢复能够证明属于同一任务外，继续返回 `OUTPUT_CONFLICT`，不得覆盖。

## 7. 组件接入

### 7.1 结构化提取

- API 请求策略使用共享输入、输出访问检查；
- worker 输入解析器在准备输入时重新检查可读性；
- publisher 在发布前重新检查输出父目录和实际写入能力；
- processor、私有 manifest、staging、恢复和不覆盖语义不变。

### 7.2 Markdown 清洗

- API 请求策略改用共享本地输入、输出访问检查；
- 本地输入 resolver 在打开源文件时重新检查；
- publisher 在最终发布时使用共享输出语义；
- HTTP 输入 allowlist、Markdown pipeline 和 staging 防护保持不变。

### 7.3 全局去重

- API 请求策略改用共享本地输入、输出访问检查；
- worker input reader 与 publisher 在真实 I/O 前重新检查；
- HTTP、S3、manifest 内容限制和 Data-Juicer adapter 边界不变。

### 7.4 文本分类

- 调用方只提供本地输入，不提供本地输出目标；
- input preparer 使用共享输入访问检查，不再检查 `CLASSIFICATION_INPUT_ROOTS`；
- 分类 staging 仍由 `CLASSIFICATION_STAGING_ROOT` 控制，不能由调用方指定；
- 分类服务调用、超时、结果契约和任务恢复保持不变。

## 8. 配置迁移

以下配置不再参与业务路径判断，并从 Settings、生产环境模板、Compose、systemd 环境说明、运行手册和测试夹具中移除：

```text
EXTRACTION_INPUT_ROOTS
EXTRACTION_OUTPUT_ROOTS
EXTRACTION_WORKER__OUTPUT_ROOTS
MARKDOWN_CLEANING_INPUT_ROOTS
MARKDOWN_CLEANING_OUTPUT_ROOTS
MARKDOWN_CLEANING_WORKER__OUTPUT_ROOTS
GLOBAL_DEDUP_INPUT_ROOTS
GLOBAL_DEDUP_WORKER__OUTPUT_ROOTS
CLASSIFICATION_INPUT_ROOTS
```

各能力的 staging 配置继续保留。升级不提供 `LOCAL_PATH_ALLOWLIST_ENABLED` 等兼容开关，也不保留 roots 为空、roots 为 `/` 和关闭检查等多套行为。部署升级后的唯一语义是：调用方本地路径按访问能力判断。

生产 `.env` 中遗留的旧变量应在发布时清理，避免运维人员误以为它们仍然生效。应用对未知遗留环境变量的处理遵循现有 Settings 策略，但运行手册和验收报告必须明确这些变量已废弃。

## 9. 错误模型

取消白名单后，不再因目录归属产生 `INPUT_PATH_NOT_ALLOWED` 或 `OUTPUT_PATH_NOT_ALLOWED`。本地访问失败应稳定区分：

- 输入路径不是绝对路径；
- 输入不存在、不是普通文件或当前进程不可读；
- 输出路径不是绝对文件路径；
- 输出父目录不存在、不是目录或当前进程不可写；
- 输出目标冲突；
- API 预检通过后，worker 实际 I/O 时路径或权限发生变化；
- 文件系统或系统级异常导致访问失败。

四项能力统一新增 `INPUT_ACCESS_FAILED` 和 `OUTPUT_ACCESS_FAILED`：前者覆盖本地输入不存在、类型错误、解析失败和不可读，后者覆盖输出父目录不存在、类型错误、解析失败和不可写。相对路径或不符合能力文件格式的请求继续使用现有请求校验错误；目标已存在继续使用 `OUTPUT_CONFLICT`。原 `INPUT_PATH_NOT_ALLOWED`、`OUTPUT_PATH_NOT_ALLOWED` 不再由本地路径分支产生，但远程 URL、协议和 bucket 拒绝仍使用各自现有错误码。

对外响应和日志不得包含凭据、内部堆栈或未经脱敏的宿主机绝对路径；内部日志可携带 `request_id`、`task_id`、调用方标识和受控失败分类，不记录文档内容。

## 10. 安全与运行边界

取消白名单后，服务可访问范围扩大为 Linux 运行账号能够访问的全部本地文件系统。生产安全边界因此从应用目录白名单转移到进程身份、Unix mode、ACL、挂载选项、容器或 systemd sandbox 和只读挂载。

实施与发布必须满足：

- API 和 worker 使用最小权限的专用非 root 账号；
- 生产密钥、系统配置和无关业务目录不能授予该账号读写权限；
- 输入只需要读权限，业务输出目录只授予必要写权限；
- 不为解决访问失败而给服务账号授予全盘权限；
- systemd hardening 或容器挂载不得被本次变更静默削弱；
- staging 清理只能作用于经过验证的任务私有目录，不能根据调用方路径执行递归删除；
- 项目规则中“不允许任意宿主机路径”的旧约束必须随实现同步更新，以本设计确认的新权限模型为准。

## 11. 测试范围

### 11.1 共享策略单元测试

- 白名单概念之外的现存可读普通文件通过输入检查；
- 相对输入、缺失输入、目录、不可读文件和解析失败被拒绝；
- 任意现存可写父目录下的绝对目标通过输出预检；
- 相对输出、缺失父目录、父路径不是目录和不可写目录被拒绝；
- 预检不创建最终文件或残留探测文件；
- 输出目标存在时交由冲突策略处理，不被访问检查覆盖；
- 符号链接解析成功时按实际目标访问，循环或失效链接安全失败；
- 错误响应不泄露绝对路径和内部异常。

### 11.2 各能力契约测试

- 结构化提取、Markdown 清洗和全局去重均接受原白名单之外的可读输入与可写输出；
- 文本分类接受原白名单之外的可读输入；
- API 预检后删除输入、撤销权限或改变输出父目录状态，worker 返回稳定访问错误；
- API 与 worker 通过同一共享策略获得一致分类；
- 目标冲突、重复消息、worker 中断和幂等恢复行为不退化；
- HTTP host/CIDR 和 S3 bucket 白名单仍然生效；
- 请求不能改变 staging 根目录，终态清理不触及调用方目录；
- 删除旧 roots 配置后应用和 worker 可以正常启动。

### 11.3 真实环境测试

- 使用与生产一致的非 root 账号运行 API 和 worker；
- 从两个不同的既有本地目录读取测试输入；
- 向两个不同的既有可写目录发布结果；
- 对无权限输入、无权限输出和缺失父目录执行负向测试；
- 核验任务状态、最终文件、日志脱敏、staging 清理及重复投递行为。

## 12. 文档与契约同步

实现时同步更新：

- 根 `AGENTS.md` 中本地路径 allowlist 与“任意宿主机路径”约束；
- 结构化提取、Markdown 清洗、全局去重和文本分类相关架构说明；
- 137 systemd 生产运行手册与环境配置示例；
- `.env.example`、Compose 环境配置和测试夹具；
- API 中文字段说明、稳定错误说明和相关 Apifox 测试用例。

API 请求字段结构不因本次设计改变。若错误码映射变化，则以实现后的 FastAPI OpenAPI 和代码为权威同步 Apifox，不在设计文档中固化未经实现验证的最终 schema。

## 13. 生产发布与验收

1. 建立共享 `LocalPathAccessPolicy`，完成四项能力的 API 与 worker 接入；
2. 移除本地 roots 配置及重复路径归属实现，保留 staging 和远程资源策略；
3. 完成共享策略单元测试、各能力契约测试和任务恢复集成测试；
4. 使用非 root 身份完成本地真实文件系统权限测试；
5. 更新项目规则、运行手册、环境配置和 Apifox 契约；
6. 在 137 记录 API 与 Task Runner 的运行账号、权限和发布前配置快照；
7. 滚动重启 API 与 Task Runner，验证服务健康和 worker 消费能力；
8. 使用 `/data/shineData/hub/txt` 以及另一处受控目录执行真实输入、输出冒烟；
9. 执行不可读、不可写、父目录缺失和目标冲突负向验收；
10. 核验 PostgreSQL 状态、最终文件、日志脱敏、远程 allowlist 和 staging 清理。

生产验收标准：四项能力不再因本地目录不属于 roots 而拒绝请求；可访问本地输入和输出成功，不可访问路径稳定失败；远程资源和内部 staging 边界不变；任务恢复、冲突和不覆盖语义保持通过。若发现权限范围超出预期，应通过收紧运行账号或挂载权限回滚访问面，而不是恢复应用内多套白名单模式。
